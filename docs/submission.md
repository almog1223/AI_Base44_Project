### 2. הגדרת הבעיה וקהל היעד

**Problem Statement**
צוות העמותה מנהל את המידע הרפואי, המיקום וההתנהגות של עשרות בעלי חיים ב-7 גיליונות מפוזרים. כתוצאה מכך טיפולים מתפספסים, בעלי חיים בטיפול רפואי יוצאים מהמחסה, ובקשות אימוץ ממתינות שבועות עד שהמאמצים מוותרים.

**Personas**
| Persona | הצורך המרכזי |
|---|---|
| רוני, מנהלת העמותה | תמונת מצב אחת: איפה כל בעל חיים ומה מצבו |
| ד"ר גיל, וטרינרית | תיק רפואי מדויק ותזכורות לטיפולים שמגיע זמנם |
| שי, רכז אימוצים | מיון מהיר של בקשות והתאמה טובה בין כלב למשפחה |
| משפחת אומנה | דרך פשוטה לדווח על התנהגות ולקבל תזכורות |
| מאמץ פוטנציאלי | לראות בעלי חיים זמינים, להגיש בקשה ולדעת מה הסטטוס שלה |

**Value Proposition**
כרטיס אחד לכל בעל חיים שמרכז מיקום, תיק רפואי והתנהגות. המערכת חוסמת אוטומטית יציאה של בעל חיים בטיפול, מזכירה על חיסונים, וסוכן AI מדרג את בקשות האימוץ. כך בקשה מקבלת מענה תוך ימים במקום שבועות.

### 4. מסע משתמש (User Flow)

**מאמץ פוטנציאלי**
דף נחיתה ← "מצאו חבר לחיים" ← גלריה מסוננת (רק בעלי חיים זמינים) ← כרטיס בעל חיים עם תכונות התנהגות מהאומנה ← "אני רוצה לאמץ" ← התחברות ← טופס בקשה ← "הבקשות שלי" עם ציר סטטוס.

**רכז אימוצים**
אזור הצוות ← לוח בקשות ← פתיחת בקשה ← "הפעל סוכן התאמה" ← ציון, נימוק, אזהרות ו-3 חלופות ← החלטה אנושית ועדכון סטטוס.

**וטרינרית**
משימות רפואיות (טיפולים שמגיע זמנם או שעבר זמנם) ← כרטיס בעל חיים ← הוספת טיפול. אם סומן "אסור לצאת", בעל החיים נחסם אוטומטית ליציאה ולאימוץ.

**משפחת אומנה**
אזור האומנה ← בעלי החיים שלי ← דיווח התנהגות שבועי. הדיווח מעדכן את התכונות שהמאמצים רואים.

### 5. מסד נתונים (Database Model)

**ישויות ושדות עיקריים**

| ישות                      | שדות עיקריים (סוג)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **User** (מובנית, מורחבת) | app_role (enum: admin, vet, coordinator, volunteer, foster, adopter), phone (text), address (text)                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Animal**                | name (text), species (enum: dog, cat), breed (text), sex (enum), birth_date_estimate (date), size (enum: small, medium, large), energy_level (enum: low, medium, high), photos (array of images), public_description (long text), intake_date (date), location_type (enum: shelter, foster, adopted), foster_id (ref → User), foster_name (text), status (enum: intake, in_treatment, available, pending_adoption, adopted), is_blocked (boolean), good_with_kids, good_with_dogs, good_with_cats, house_trained (enum: yes, no, unknown) |
| **MedicalRecord**         | animal_id (ref → Animal), type (enum: vaccination, deworming, flea_treatment, surgery, medication, checkup, special_diet), description, medication (text), start_date, end_date, next_due_date (date), no_leave (boolean), performed_by (ref → User), status (enum: scheduled, active, done)                                                                                                                                                                                                                                              |
| **BehaviorReport**        | animal_id (ref → Animal), reporter_id (ref → User), report_date (date), house_trained, good_with_kids, good_with_dogs, good_with_cats, leash_walking (enum), energy_observed (enum), notes (long text), photo (image)                                                                                                                                                                                                                                                                                                                     |
| **AdoptionApplication**   | applicant_id (ref → User), applicant_name, applicant_phone, applicant_email (text), animal_id (ref → Animal), home_type (enum), has_kids, has_dogs, has_cats (boolean), hours_alone_per_day (number), experience (enum), preferred_size, preferred_energy (enum), motivation (long text), status (enum: new, in_review, meeting_scheduled, approved, adopted, rejected), assigned_coordinator (ref → User)                                                                                                                                |
| **MatchRecommendation**   | application_id (ref → AdoptionApplication), animal_id (ref → Animal), score (number 0–100), reasoning (long text), warnings (text)                                                                                                                                                                                                                                                                                                                                                                                                        |

**קשרים**

- Animal **1:N** MedicalRecord: לבעל חיים יש הרבה טיפולים.
- Animal **1:N** BehaviorReport: הרבה דיווחי התנהגות לאורך זמן.
- User (אומנה) **1:N** Animal: משפחה יכולה להחזיק כמה בעלי חיים.
- User (מאמץ) **1:N** AdoptionApplication
- Animal **1:N** AdoptionApplication: על בעל חיים יכולות להיות כמה בקשות.
- AdoptionApplication **N:M** Animal דרך ישות הקישור MatchRecommendation: לכל בקשה כמה המלצות, וכל בעל חיים יכול להיות מומלץ לכמה בקשות.

### 8. סוכן AI ואוטומציה

**סוכן התאמת אימוץ**

- **תפקיד:** מקבל בקשת אימוץ ומשווה אותה לבעלי החיים הזמינים: גודל ואנרגיה מול סוג הבית ושעות לבד, ילדים ובעלי חיים אחרים מול נתוני ההתנהגות, וניסיון המאמץ. מחזיר ציון 0–100, נימוק, אזהרות ו-3 חלופות.
- **ערך מוסף:** מקצר את מיון הבקשות משבועות לדקות. ההתאמה מבוססת על דיווחי האומנה בפועל ולא על ניחוש, ופחות אימוצים חוזרים לעמותה.
- **הרשאות ולמה:** קריאה בלבד ל-Animal (זמינים בלבד), ל-BehaviorReport ול-AdoptionApplication. יצירה רק של MatchRecommendation. אין לו גישה למידע רפואי או לפרטי קשר, ואין לו הרשאה לשנות סטטוס. הנימוק הוא עיקרון Least Privilege: הסוכן ממליץ, והאדם מחליט.
- **חיבורים:** ישויות האפליקציה ב-Base44 וה-LLM המובנה של הפלטפורמה. אין לו חיבור לשירותים חיצוניים.

**אוטומציות (ללא AI)**

- **חסימה:** טיפול פעיל שמסומן "אסור לצאת" חוסם את בעל החיים ומונע לסמן אותו כ"זמין".
- **תזכורות במייל:** כל יום נשלחות תזכורות על חיסונים שמגיע זמנם בשבוע הקרוב, לאומנה ולווטרינרית.
- **תזכורת דיווח:** משפחת אומנה שלא דיווחה 7 ימים מקבלת תזכורת.

### שיטת העבודה

עבדנו במתודולוגיית Spec-Driven Development: קודם אפיון מאושר, אחר כך תוכנית, ורק אז בנייה. הבנייה נעשתה בצ'אט של Base44 בפרומפטים מדורגים, פרומפט לכל שכבה (נתונים, דמו, הרשאות, מסכים, לוגיקה, סוכן), עם בדיקה אחרי כל שלב. הפרומפטים נכתבו באנגלית, כי המודל מדייק יותר בהוראות טכניות, וביקשו ממשק בעברית RTL.

### אתגרים והחלטות במהלך הבנייה

- **משתמשי דמו:** הפלטפורמה לא מאפשרת ליצור חשבונות. שקלנו לקשר את כל הרשומות לחשבון אחד, אבל זה היה שובר את הדגמת ההרשאות, כי מאמץ היה רואה את כל הבקשות. לכן בחרנו בשדות שם טקסטואליים ובקישור סלקטיבי.
- **מגבלת קרדיטים:** כל פרומפט עולה קרדיט. לכן הפרומפטים נבנו מראש בקובץ ומוקדו כך שכל אחד יבצע שכבה שלמה. הגדרות ועריכות נתונים נעשו ידנית ב-Dashboard, בלי לבזבז קרדיטים.
